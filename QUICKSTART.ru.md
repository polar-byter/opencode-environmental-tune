# Быстрый старт (RU): кит для OpenCode на примере Java / Spring Boot

> Инструкция «с нуля»: как подключить кит к своему проекту и начать работать в OpenCode.
> English version: [QUICKSTART.en.md](QUICKSTART.en.md)

---

## 1. Что это такое

Этот кит превращает OpenCode в схему **«мозг + исполнители»**:

- 🧠 **Мозг** (`build`, облачная модель) — планирует задачу, пишет **каркас кода с техническим заданием (ТЗ)**, сразу пишет **тесты**, проверяет результат.
- 🛠 **Исполнитель** (`executor`, локальная модель в LM Studio) — заполняет **только тела методов** строго по ТЗ. Ничего лишнего не трогает.

Цикл работы всегда такой:

```
ты:   Нужен API списка задач. Сначала покажи план.
мозг: предлагает план и объясняет порядок модулей
ты:   План подходит. Реализуй его целиком.
мозг: каркас + ТЗ + тесты (тесты пока красные — это нормально)
      └─ передаёт исполнителю по одному методу
исполнитель: заполняет тело по ТЗ
мозг: проверяет код и тесты → отмечает модуль готовым → сам начинает следующий
      в конце — результат и статистика всей задачи
```

Пример ниже — проект на **Java (Spring Boot)**. Схема одинаковa для любого языка: меняются только команды тестов.

## 2. Что нужно установить

| Что | Зачем | Проверка |
| --- | --- | --- |
| OpenCode | сам агент | — |
| LM Studio | локальная модель-исполнитель | `py kit/check_env.py` |
| Python 3.13 | **только** утилиты кита | `py --version` (macOS, Linux: `python3 --version`) |
| JDK 21 | компилировать Java | `java -version` |
| Maven | сборка и тесты Java | `mvn -v` |

> Python нужен киту (поиск Obsidian и проверки), а не твоему Java-проекту.
>
> Команды в этой инструкции написаны для Windows, где Python запускается командой `py`. На macOS и Linux вместо `py` пиши `python3`. Мозг узнаёт об этом из `AGENTS.md` и сам выбирает нужную команду.

В LM Studio нужно **загрузить модель** (кнопка **Load**) и включить сервер: **Developer → Start Server**.

## 3. Шаг 1. Создать Java-проект

1. Открой [start.spring.io](https://start.spring.io)
2. Заполни:
   - **Project:** Maven
   - **Language:** Java
   - **Spring Boot:** последняя стабильная 3.x
   - **Java:** 21
   - **Dependencies:** `Spring Web`, `Validation`
3. Нажми **Generate** → скачается zip.
4. Распакуй его, например в `D:\PROJECTS\task-api`.

Получится примерно так:

```
task-api/
├── pom.xml
└── src/
    ├── main/java/com/example/taskapi/
    └── test/java/com/example/taskapi/
```

---

## 4. Шаг 2. Положить кит в проект

Скопируй в корень `task-api/` четыре вещи:

```
opencode.jsonc        ← агенты и модели
AGENTS.md             ← правила работы
kit/                  ← утилиты (поиск Obsidian, проверка среды)
.opencode/            ← команды /plan-project и /module
```

Итого в корне проекта должно быть:

```
task-api/
├── opencode.jsonc
├── AGENTS.md
├── kit/
├── .opencode/
├── pom.xml
└── src/
```

---

## 5. Шаг 3. Настроить `AGENTS.md` под Java

Открой `AGENTS.md` и отредактируй **две секции** с пометкой `# EDIT`.

**Секция `Project stack`:**

```md
## Project stack  # EDIT: language, build tool, test command
- Language: Java 21 (`java -version`). Build tool: Maven (`mvn`).
- Tests: JUnit 5. Maven writes one JUnit XML file per test class into `target/surefire-reports`.
- Test command (always through task_metrics):
  `py kit/task_metrics.py test --task <ID> --junit-dir target/surefire-reports -- mvn -q test`
- Compile only: `mvn -q compile`.
- Run the app: `mvn spring-boot:run`.
```

**Секция `Project layout`:**

```md
## Project layout  # EDIT: folders and files of this project
- `src/main/java/com/example/taskapi/` — application code.
- `src/test/java/com/example/taskapi/` — tests.
- `pom.xml` — Maven build file.
```

> Всё остальное в `AGENTS.md` менять не нужно. Команды `/module` и `/plan-project` уже языко-независимы.

---

## 6. Шаг 4. Проверить среду

Эта проверка нужна, чтобы убедиться, что мозг сможет обратиться к локальному исполнителю. После открытия проекта попроси мозг:

```text
Проверь среду через kit/check_env.py. Прочитай результат пробного
запроса к модели и объясни, что нужно настроить, если подключение не работает.
```

Мозг выполнит проверку сам. Итоговая строка `ready for use` появляется, только если конфиг верный, LM Studio отвечает и пробный запрос к модели прошёл. Возможные проблемы описаны в разделе **11. Частые проблемы**.

### Проверить, что статистика читает результаты тестов

Скрипт статистики должен понимать, сколько тестов прошло и сколько упало. Проверь это один раз сам, в терминале в корне проекта:

```bash
py kit/task_metrics.py check --junit-dir target/surefire-reports -- mvn -q test
```

- `CHECK OK` — всё настроено. Упавшие тесты на этом шаге не мешают.
- `CHECK FAILED` — скрипт не может прочитать результат. Ниже будут подсказки: например, Maven не найден, проект не собирается или отчёты не появились.

Для других языков команда своя — смотри таблицу «Подключение своего языка» в `README.md`. Мозг тоже выполняет эту проверку перед каждой задачей и не начинает писать код, пока она не проходит.

## 7. Шаг 5. Запустить OpenCode

Открой OpenCode **в папке `task-api`** (там, где лежит `opencode.jsonc`).

Проверь, что всё видно:
- набери `/` — должны быть команды `/plan-project` и `/module`;
- спроси: «Прочитай план работ» — мозг найдёт Obsidian через `kit/find_vault.py` (или возьмёт `currentsteps.md`).

---

## 8. Шаг 6. Спланировать проект

Напиши в чат OpenCode:

```text
Нужен REST API списка задач на Spring Boot: создавать, просматривать,
завершать и удалять задачи. Данные пока храни в памяти.
Сначала покажи план и объясни порядок работы.
```

Мозг сначала составит план: разобьёт задачу на модули и запишет список работ. До согласования код не пишет.

Пример результата:

```md
## Modules
- [ ] model      — Task + хранилище
- [ ] service    — list / create / complete / delete
- [ ] controller — REST-ручки
```

Модули и их порядок выбирает мозг. В этом примере сначала нужны данные (`model`), затем операции с ними (`service`), затем HTTP-запросы к этим операциям (`controller`). Знать эти названия заранее не нужно.

Проверь, что план соответствует твоей задаче, и ответь: «План подходит. Реализуй его целиком, проверь результат и покажи статистику».

---

## 9. Шаг 7. Мозг выполняет согласованный план

После согласования мозг сам начинает первый модуль по зависимостям в плане. Выбирать модуль и запускать его отдельной командой не нужно.

Что произойдёт автоматически:

1. Мозг создаст **каркас** метода с Javadoc-ТЗ и заглушкой:
   ```java
   public Task create(String title) {
       throw new UnsupportedOperationException("TODO: executor");
   }
   ```
2. Мозг создаст **тесты** `TaskServiceTest.java` и запустит их через `kit/task_metrics.py` — тесты **красные** (так надо).
3. Мозг вызовет **исполнителя** заполнить тело метода по ТЗ.
4. Исполнитель заполнит **только тело**.
5. Мозг проверит код и снова запустит тесты. Если упал тест — вернёт код исполнителю на переделку. Если проект не собирается из-за настройки — исправит настройку или спросит тебя, а не гоняет исполнителя. После успешной проверки отметит модуль готовым и сам начнёт следующий, зависимости которого уже готовы.
6. Если один кусок кода вернули исполнителю 3 раза или тесты 3 раза подряд не дали результата, скрипт статистики останавливает задачу (`STOP`). Мозг объяснит, что случилось, и будет ждать твоего решения: уточнить задание, поправить тесты или настройку. Так цикл «тест — переделка» не может крутиться бесконечно.

Мозг продолжает, пока не выполнит весь согласованный план. Он обращается к тебе, если не хватает доступа или инструментов либо нужно принять решение, которое меняет задачу. Обычный переход между модулями нового согласования не требует.

Ты можешь поручить весь проект одной задачей. Разбивать его на небольшие задания для исполнителей должен мозг. Команда `/module` остаётся удобной для отдельного модуля, если ты сам хочешь ограничить задачу им.

## 10. Шаг 8. Проверить и запустить

Мозг проверяет общую работу модулей и показывает результат. В отдельном разделе он выводит статистику из `kit/task_metrics.py`: токены LM Studio и остальных моделей, возвраты кода на доработку и полностью успешные запуски тестов. Статистика относится ко всей задаче.

Чтобы проверить API в работе, напиши:

```text
Запусти приложение и проверь создание, просмотр, завершение и удаление
задачи через API. Покажи результат проверки и как остановить приложение.
```

Мозг выполнит запуск и запросы сам. Если какая-то проверка не выполнена, он должен указать это в результате.

## 11. Частые проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `Result: test failed` в `check_env` | LM Studio не запущен / модель не загружена | Developer → Start Server; нажать Load у модели |
| Команд `/module` не видно | `.opencode/` не скопирован или OpenCode открыт не в корне проекта | Проверь папку проекта |
| `mvn` не найден | Maven не установлен / не в PATH | Установи Maven, перезапусти терминал |
| Тесты не компилируются | Импорта нет в каркасе (исполнитель импорты не добавляет) | Скажи мозгу: «добавь недостающий импорт в каркас» |
| `CHECK FAILED` | Скрипт не может прочитать результат тестов | Прочитай подсказки под строкой; проверь команду тестов в `AGENTS.md` |
| Мозг пишет `STOP` и ждёт | Сработал защитный лимит: переделки или сборка | Прочитай причину, прими решение и скажи мозгу продолжать |
| Мозг всё делает сам | Не читает `AGENTS.md` | Проверь, что `AGENTS.md` в корне проекта |
| `currentsteps.md` не создаётся | Obsidian не найден | Это нормально: план будет в проекте |
