# Повтор эксперимента из OpenCode Desktop

Цель: поставить ТЗ в Desktop и увидеть работу Мастер Чифа и исполнителей
в чате и дашборде. Пользователь выбирает модели и описывает результат;
служебные скрипты запускает агент по AGENTS.md.

## Подготовленный проект на этом компьютере

`D:\Projects\ActiveProjects\AIProjects\tictactoe-desktop-20261015`

Отдельная чистая папка с копией текущего кита и `TASK.md`, без исходников игры,
старых журналов и сессий. Предыдущий незавершённый эксперимент
`tictactoe-kit-clean-20261015` сохранён отдельно.
Выбор моделей перенесён из рабочего кита; доступность провайдера этим не проверяется.
Подготовка папки не является успешным прогоном игры.

## Что сделать

1. Открой **OpenCode Desktop → Open project** и выбери эту папку.
2. Если хочешь изменить модели, напиши агенту: **«Открой настройки моделей этого
   проекта. Пока не начинай реализацию»**. В окне выбери Master Chief и Executors
   или модель из OpenRouter для каждой роли. Для своего API введи ключ в окно,
   нажми **Prepare OpenCode**. Русский включается через **Language → Russian**.
   После нового ключа полностью перезапусти Desktop из меню Windows.
   После изменения моделей попроси агента подготовить общий сервис по AGENTS.md,
   затем заново открой проект и создай новый чат. Существующий чат сам модель не меняет.
3. В новом чате выбери агент **build** и вставь:

   > Прочитай AGENTS.md и TASK.md. Реализуй эту игру целиком по правилам кита:
   > Мастер Чиф делает архитектуру, каркасы, тесты и ревью; тела реализуют выбранные
   > executor и executor-fast. План утверждаю, работай автономно до проверки результата.
   > Веди план в currentsteps.md этой игры. Сам подготовь конфигурацию для текущего
   > Desktop, открой учёт с фактическим ID этой сессии и новый дашборд. До делегирования
   > опубликуй архитектуру и реестр функций; передавай исполнителям файл текущего
   > прогресса. Дай ссылку на дашборд и путь проекта сразу. В конце проверь запуск игры,
   > полный набор тестов и покажи итог с токенами и файлом запуска. Не запускай задачу
   > через отдельный CLI run/standalone: я хочу видеть её в этом чате Desktop.
4. Открой ссылку от агента. На дашборде должны появляться архитектура, фактические
   модели, текущая работа, заявленный/принятый прогресс функций, детализация работ,
   тесты и доступные токены. Settings открывает настройки именно этой игры.
   В конце проверь сообщение завершения, папку и файл запуска.

Если настройки уже подходят, второй шаг можно пропустить. Для LM Studio сначала
самостоятельно загрузи нужную модель и включи сервер. Для OpenCode/своего API
LM Studio не требуется. Подключение провайдера должно быть доступно в Desktop;
каталог OpenRouter не выполняет авторизацию.

## Если агент остановился

При лимите 429, ошибке ключа или недоступной модели остановка видна в чате
и журнале. Дождаться доступности или выбрать другого исполнителя решает пользователь;
агент не должен молча менять провайдера или сам реализовывать его задание.
В прошлой проверке выбранный Poolside вернул 429; сейчас доступность не проверялась.

Если браузер не открылся, попроси агента повторно открыть дашборд текущей задачи;
новый `start` для того же ID не нужен. Порт выдаёт текущий запуск: старые ссылки
из заметок о предыдущих опытах могут уже не работать.

Получение списка моделей не подтверждает генерацию и инструменты. Доступные токены
появляются после завершённых сообщений; отсутствие данных означает «неизвестно».
Эксперимент завершён после принятого ревью, полного набора тестов и проверки
работающей игры, а не по одному индикатору заполнения функций.

Для нового опыта на другом компьютере агент копирует `opencode.jsonc`, `AGENTS.md`,
`kit/` и `.opencode/commands/` в новую папку, добавляет ТЗ и закрепляет её собственный
`currentsteps.md` в Work plan. Локальный выбор моделей переносят отдельно без ключей;
готовые исходники игры и `.metrics/` не копируют. Служебную подготовку выполняет агент.
