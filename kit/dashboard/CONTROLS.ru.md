# Управление задачей из дашборда

Реализовано 15.10.2026 по прямому разрешению пользователя. Рабочая страница
остаётся на HTML/JavaScript. Учебные `simple.py` и `simple.html` не изменены.

## Поведение

| Действие | Результат |
| --- | --- |
| Приостановить | Запретить новые операции кита, прервать основную сессию и всех её исполнителей, дождаться отсутствия активных связанных сессий. Сохранить код, план, историю. |
| Продолжить | Проверить сохранённую паузу, отправить основной модели запрос продолжить ту же задачу из плана и проверить незавершённую попытку; сохранить task ID. |
| Остановить | Прервать все связанные сессии и отменить их отложенные входные сообщения. Зафиксировать отмену без объявления успешного завершения. |
| Удалить | Сначала подтверждённая остановка, затем удаление сессий и журнала выбранной задачи. Исходники приложения остаются. |

Пауза прерывает текущую генерацию; продолжение не обещает восстановить тот же
поток с того же токена. Перед продолжением требуется ревью частичных изменений.
Другие задачи, проекты и загруженные в LM Studio модели не останавливаются.
Пауза/отмена должна блокировать последующие delegate/test/review этого task ID.
Сбой API не должен превращаться в сообщение об успешной остановке.

## Состав реализации

- Независимое хранилище состояния управления в `.metrics/.task-controls/`:
  состояние, запрос и результат операции переживают перезапуск дашборда.
- Адаптер установленного OpenCode: список корневых/дочерних сессий, active,
  interrupt, inbox cancel, prompt, delete. Без запуска нового сервера и смены модели.
- Контроллер задачи: проверка принадлежности, обход всех потомков, сверка активности,
  блокировка параллельных действий, идемпотентные повторные нажатия.
- HTTP POST с уже используемыми проверками Origin и UI-токена; только выбранный
  task ID, без пути, команды, модели и произвольного session ID от браузера.
- Кнопки и отображение состояний: выполняется / приостанавливается / пауза /
  продолжается / останавливается / отменена / ошибка. Удаление требует подтверждения.

Если одна сессия используется несколькими учётами, управление старым учётом
не должно прерывать новый или удалять его историю: запрос отклоняется.
Неизвестная версия API и неподтверждённая остановка показываются как ошибка.
Контроль предназначен для общего сервера Desktop. Изолированный сервер нельзя
незаметно подменять общим и объявлять его остановленным.

## Восстановление устойчивого просмотра

Названия настроенных моделей читаются без проверки наличия API-ключа.
Ошибки конфигурации, реестра функций и чтения сессий изолируются: доступная
архитектура, задания, журнал и другие сведения продолжают отображаться.

## Ограничения и восстановление

Поддерживается API установленного OpenCode Desktop 2.0.26: `session.interrupt`
с query-параметром `resume=false`, `session.active`, `session.inbox.*`,
`session.prompt` с полем `text`, `session.remove`. Перед действием проверяются
возможности установленного сервера. Сессии сверяются по точному каталогу и родителю,
список страниц ограничен; циклы и чужие корни отклоняются. Команды идут в общий
сервис Desktop, без запуска `standalone` и без подмены моделей. Для новых задач
лаунчера в start сохраняется режим сервера; известный private/неизвестный режим
из лаунчера отклоняется. Старые журналы без этой отметки предполагают общий сервис:
для частных серверов управление из этой страницы не поддерживается.

Операция работает в фоне, POST возвращает 202. Состояние записывается атомарно,
блокировка освобождается ОС при падении процесса. После перезапуска незаконченная
операция помечается неподтверждённой; продолжение автоматически не дублируется.
Повторная остановка безопасна. Повтор удаления после частичного успеха не требует
повторного удаления уже удалённой семьи. Если журнал занят, его удаление отклоняется.
Повреждённое состояние блокирует исполнение до диагностики, а не разрешает его.

Пауза сохраняет отложенные сообщения; продолжение отправляет управляющий запрос
в ту же основную сессию. Отмена очищает очередь каждого потомка. Активность всего
дерева и его стабильность сверяются дважды. Сохранённое состояние запрещает новые
delegate/test/review/finish. Кнопка продолжения не сбрасывает защитные лимиты.
Если сработал лимит, нужно отдельное решение пользователя по обычному протоколу.

Это управление выполнением связанных сессий на общем сервисе, а не выключение
провайдеров или серверов моделей. Вручную запущенные внешние программы и посторонние
задачи не завершаются. Пока задача на паузе/отменена, не запускайте её вручную
другим запросом в Desktop: кит запрещает новые операции, но сторонний агент может
обойти инструкции. Удаление папки проекта — отдельное действие вне этой кнопки.

## Проверки

Автотесты покрывают дерево сессий и чужой проект; паузу и возобновление; отмену и
очереди; ошибки и тайм-аут API; повторные нажатия и перезапуск; удаление только
метрик выбранной задачи; сохранность кода приложения; защиту POST; отображение
при отсутствующем ключе и повреждённом вспомогательном файле.
На реальном общем API 2.0.26 отдельно проверены две сессии с очередью и полный
контроллер pause → cancel → delete на второй временной задаче с потомком.
В обоих прогонах сообщения помещались в очередь с `resume=false`, модели не
вызывались; очередь очищена, сессии удалены. Возобновление проверено контрактными
тестами без платной генерации; прерывание живой генерации предстоит проверить
в следующем пользовательском эксперименте. Полный набор завершённого кода:
`py kit/task_metrics.py test --task <ID> --scope full -- py -m kit.test_completed`.
