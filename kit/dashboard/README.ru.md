# Дашборд: учебный маршрут

Здесь лежит каркас, который ты постепенно реализуешь сам. Начинаем с Python:
одна строка JSON, затем файл, затем вывод в терминале. Первая страница появится
после того, как чтение и сводка уже работают.

Полный план и уроки находятся в папке **Дашборд OpenCode** выбранного Obsidian Vault.
`currentsteps.md` в корне Vault хранит текущий подшаг и последние результаты.

## Что открывать сейчас

Активная функция и первое действие указаны в **currentsteps.md** в корне Vault.
Отдельный текущий статус здесь не дублируем. Порядок этапов - в заметке
**02. План разработки**, упражнения сводки и страницы - в заметке
**04. Этапы 2 и 3. Сводка и страница**. Таблица ниже - повторение первого этапа.

Русские подсказки находятся в заметках Obsidian, а не в коде: основной урок 04
и справочник **06. Подсказки к функциям**. В коде остаются английские спецификации.
Подсказки содержат цель, пример и небольшие действия по порядку. Сначала
пробуй пункт 1, а не всю функцию сразу. Если пункт отмечен как промежуточный опыт,
итоговый тест ещё может не пройти. «Позже» означает: текущую функцию менять не нужно.

Проверка принятой `test_runs` (6 тестов):

```powershell
py -m unittest kit.dashboard.tests.test_journal.Step1Tests -v
```

`brief_summary` также принята. Первое упражнение страницы - `simple.task_view`:
соединить готовые чтение файла и сводку. Подробности в уроке 04, раздел 3.1.
Функция принята 13.10.2026: все 6 проверок проходят. Следующий раздел урока - 3.2,
HTTP перед обработчиком сервера; сам сервер ещё не реализован.

Проверка task_view:

```powershell
py -m unittest kit.dashboard.tests.test_simple.Iteration3TaskView -v
```

Тесты будущих обработчиков сервера для проверки этой функции не запускаем.

Для упражнения Handler.send_bytes подготовлено 5 проверок. Объяснение self и
пример одного HTTP-ответа находятся в уроке 04, раздел 3.3.1. После реализации:

```powershell
py -m unittest kit.dashboard.tests.test_simple.Iteration3SendBytes -v
```

Метод принят 13.10.2026: все 5 проверок проходят. Остальные функции сервера
пока заглушки, запускать сервер ещё рано.

Упражнение do_GET разобрано на части А-Д в уроке 04, раздел 3.3.2.
Сначала проверка Host, без чтения страницы и сводки. После реализации этой части:

```powershell
py -m unittest kit.dashboard.tests.test_simple.Iteration3GetHost -v
```

Iteration3GetRoutes проверяет остальные ответы; его 9 тестов запускаем после
следующих частей, не для проверки одного Host. Тело do_GET пишет пользователь.

Вся do_GET принята 13.10.2026: все 14 тестов проходят (5 Host + 9 ответов).
Пользователь вынес отправку после try/except: ошибки подготовки дают 400/500,
а ошибка соединения не вызывает второй ответ. Разбор находится в части Д урока.
make_server и main ещё заглушки; запускать сервер пока рано.

Для make_server подготовлен подробный урок 04, раздел 3.3.3, и 6 тестов.
Функция создаёт локальный HTTPServer, сохраняет полный journal_path и возвращает
объект, не начиная обработку запросов. Тело пишет пользователь. Проверка:

```powershell
py -m unittest kit.dashboard.tests.test_simple.Iteration3MakeServer -v
```

До реализации эти проверки ожидаемо красные; main пока не пишем и не запускаем.

| Очередь | Функция | Результат |
| --- | --- | --- |
| 1 | `journal.parse_event` | Строка JSON превращается в проверенный словарь |
| 2 | `journal.read_events` | Файл превращается в список событий |
| 3 | `console.main` | События видны в терминале |

Проверка первой функции из корня репозитория:

```powershell
py -m unittest kit.dashboard.tests.test_journal.Step1ParseAndRead.test_parse_event_checks_shape -v
```

Пока вместо тела стоит `NotImplementedError`, красный тест ожидаем. После реализации
тест должен показать `OK`. Для проверки чтения файла понадобятся также:

```powershell
py -m unittest kit.dashboard.tests.test_journal.Step1ParseAndRead kit.dashboard.tests.test_learning.Iteration1Reader -v
```

После реализации `console.main` проверь весь первый этап:

```powershell
py -m unittest kit.dashboard.tests.test_journal.Step1ParseAndRead kit.dashboard.tests.test_learning.Iteration1Reader kit.dashboard.tests.test_learning.Iteration1Console -v
py -m kit.dashboard.console kit/dashboard/examples/events.jsonl
```

Ожидаемый ручной вывод начинается с `Events: 5`, затем показывает start, test, halt,
resume и finish с их временем. Это выдуманный учебный файл, не статистика реальной задачи.

## После первого этапа

`work_item` — задание исполнителю, например реализация одного класса. Функция
`work_items()` позже соберёт историю этих заданий; `work_item_count` в полной
сводке будет их количеством. Повторные попытки одного задания не увеличивают
число заданий. Старое поле журнала `piece` уже преобразуется в `work_item`
при чтении; исторические файлы менять не нужно.

1. `task_status`, `test_runs`, `brief_summary`: краткая сводка одной задачи без сложной истории заданий.
2. `simple.py` и `static/simple.html`: сервер с двумя адресами, одна страница, кнопка обновления.
3. Несколько задач, история заданий и лимиты: постепенно подключаем старые модули.
4. Экспорт OpenCode, токены, кэш и живая лента.
5. Автообновление, затем настройки моделей с защитой POST.
6. Отдельный этап React при желании: Python API остаётся прежним.

`py -m kit.dashboard` — будущий полный сервер. Его старые номера `step 1.x` ...
`step 10.x` обозначают прежний план, а не новый порядок обучения.
`JournalTail`, `work_items`, `guard_status`, `summary`, остальные серверные модули
и полная `static/app.js` понадобятся позже.

`py -m kit.dashboard.simple ...` тоже пока каркас. Запускай сервер после завершения
его учебного этапа; готового работающего сайта сейчас нет.

Пишем обычные `for` и `if`, пользуемся явными переменными. Краткость не является
критерием качества. Помощник проверяет код, объясняет ошибки и готовит следующий урок.
