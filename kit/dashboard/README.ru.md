# Дашборд

Локальная страница, на которой видно, что происходит с задачей: этап, задания
исполнителям, тесты, ревью, токены и итоговый отчёт. Дашборд только читает журнал
задачи (`.metrics/<ID>/events.jsonl`) и сессии OpenCode; правила работы задаёт
`kit/task_metrics.py`.

## Управление рабочей задачей

Над обзором доступны «Приостановить», «Продолжить», «Остановить» и
«Удалить задачу». Действие относится к выбранному task ID и всей его семье
сессий на общем сервере OpenCode Desktop. В ходе операции показывается переходное
состояние; ошибка API не выдаётся за успешную остановку. Удаление требует
подтверждения и сохраняет исходники приложения. Подробности и ограничения —
[CONTROLS.ru.md](CONTROLS.ru.md).

Настроенные модели показываются без API-ключа в окружении дашборда. Ошибка
вспомогательного источника не скрывает остальные доступные сведения.

Полная проверка кода кита из корня проекта:
`py kit/task_metrics.py test --task <ID> --scope full -- py -m kit.test_completed`.

## Рабочий автозапуск

В подключённом проекте (`opencode.jsonc` и `kit/`) Мастер Чиф вызывает
`task_metrics.py start` при начале задачи. Эта команда автоматически запускает
один локальный сервер проекта и открывает страницу нужного task ID. Пользователь
пишет ТЗ в OpenCode; отдельную команду дашборда он не вводит.

`launcher.py` управляет запуском, готовностью и повторным использованием процесса.
`runtime.py` обслуживает JSON API и `static/runtime.html`. Страница обновляется
каждые 2 секунды, показывает сводку и события, позволяет выбрать задачу и читать отчёт.
Журнал она читает через `journal.read_events` и `journal.brief_summary`.

Служебные сведения и журнал сервера находятся в `.metrics/.dashboard/`.
Сервер слушает только `127.0.0.1`. Закрытие вкладки и `finish` не выключают сервер:
он остаётся для следующей задачи и просмотра отчёта. Штатный останов для диагностики:
`py -m kit.dashboard.launcher --stop`; останавливается только проверенный сервер проекта.
Смена и загрузка моделей в эту часть не входят.

Если запуск не удался, CLI возвращает `dashboard.status=unavailable`; журнал уже
сохранён. Агент сообщает ошибку и не повторяет `start` с тем же task ID.
Для повтора открытия: `py -m kit.dashboard.launcher --task <ID>`.
Это служебные команды агента и разработчика, не обязательные действия пользователя.

Для автоматических тестов: `start --no-dashboard`, переменная
`OPENCODE_KIT_DASHBOARD=off`; `start --no-browser` запускает сервер без открытия окна.
Обычный локальный пользовательский сценарий использует автозапуск по умолчанию.

API рабочего просмотра:

| GET | Ответ |
| --- | --- |
| `/api/health` | Идентификатор сервера и проект, без управляющего токена |
| `/api/tasks` | Список задач проекта |
| `/api/task?task=<ID>` | Базовая сводка и последние 30 событий |
| `/api/report?task=<ID>` | Текст итогового отчёта |

Механизм связи срабатывает после команды `start`, а не при отправке любого
сообщения OpenCode. Выполнение раннего `start` агентом остаётся обязательной инструкцией.
Рабочая страница написана на обычных HTML и JavaScript, без фреймворков.

## Рабочий просмотр задач

Во вкладке «Обзор» видны этап, реальные модели Master Chief и исполнителя,
ссылка на архитектуру и прогресс функций. В «Детализация работ» — задания,
попытки, файлы, тесты, ревью, функции и публичные сообщения и инструменты OpenCode.
Журнал опрашивается каждые 2 секунды, сессии читаются в фоне с кэшем на 15 секунд.

`tracking.py` хранит снимок архитектуры и именованный реестр функций в
`.metrics/<task>/progress/plan.json`. Master Chief публикует его до делегирования
командой `py -m kit.dashboard.tracking --task ID --architecture ARCHITECTURE.md --functions .metrics/ID/functions.json`.
Договор реестра и сообщений исполнителя указан в корневом AGENTS.md, разделе Task metrics.
Исполнитель обновляет только назначенный файл своей попытки через инструмент редактирования.
Предварительно реализованные функции и принятые на ревью показаны отдельно;
устаревшая текущая функция скрывается через 90 секунд. Без реестра количество неизвестно.
Для старых задач текущий документ проекта помечен отдельно от снимка задачи.

«Настройки моделей» запускает существующее отдельное окно `kit.configurator.app`
в корне проекта этого сервера. Повторный клик использует живой процесс.
Кнопка ничего не сохраняет и не применяет автоматически; выбор выполняется в конфигураторе.
POST проверяет Host, Origin и отдельный UI-токен. Команда и корень проекта не задаются браузером.
Подготовка следующего сервера остаётся задачей `run_opencode.py`.

Вкладка «Токены» показывает отдельные колонки входа, выхода, рассуждений,
чтения и записи кэша по моделям, роли и число сообщений. В процессе используются
завершённые сообщения из фонового экспорта; после finish — сохранённые данные
журнала, совпадающие с итоговым отчётом. Категории не складываются в общий расход,
неизвестные значения не заменяются нулями. Денежная стоимость не вычисляется.

Блок завершения показывает время и результат итогового полного прогона. Без
зелёного полного прогона или при заданиях без ревью успешная проверка не заявляется.
Кнопка открытия папки вызывает файловый менеджер для корня проекта сервера.
Ссылка на файл запуска открывает только его текст в браузере. Обычные root-файлы
run/start с расширением ps1/sh/cmd/bat/py находятся автоматически; нестандартный
скрипт Master Chief указывает в `.metrics/<task>/progress/result.json`, поле launcher.

До завершения над вкладками показывается блок «Сейчас в работе»: модель,
задание, текущее действие или последнее известное, свежая отметка функции,
принятые задания, реализованные функции, вход и выход токенов и время с начала.
Этот блок виден также при просмотре детализации и токенов. Пауза имеет отдельную
подпись; после finish его заменяет итоговый блок. Свежее действие требует среза
не старше 30 секунд и отметки действия не старше 90 секунд; иначе показана история.
Отсутствующая сессия или реестр явно отмечены. Shell-команды и рассуждения не выводятся.
Кнопка «В работе: N» переключает на последнюю текущую задачу этого проекта;
в списке задач виден статус. Завершённую задачу по URL автоматически не подменяем.

## Учебные примеры

Два небольших примера написаны вручную, пока изучался Python. Они работают
отдельно от рабочего дашборда и показывают одну задачу из файла журнала:

```powershell
py -m kit.dashboard.console kit/dashboard/examples/events.jsonl
py -m kit.dashboard.simple kit/dashboard/examples/events.jsonl
```

`console.py` печатает события в терминал, `simple.py` с `static/simple.html`
открывает страницу с краткой сводкой. `examples/events.jsonl` — выдуманный
журнал для этих примеров, не статистика реальной задачи.
