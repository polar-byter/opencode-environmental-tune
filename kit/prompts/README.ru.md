# Промпты: памятка для человека

Здесь рабочий текст разделён по ролям и коротким Markdown-разделам:

| Файл | Что объясняет модели |
| --- | --- |
| [master-chief.md](master-chief.md) | План, общие контракты, зависимости, вызов контроллера, приёмка и завершение |
| [executor.md](executor.md) | Границы одного поручения, прогресс и остановка |
| [executor-fast.md](executor-fast.md) | Те же ограничения для маленького исправления |
| [bug-fixer.md](bug-fixer.md) | Одна попытка исправления с сохранением контракта |

`Role` означает роль, `Input` — полученные данные, `Allowed changes` — разрешённые
изменения, `Progress` — промежуточный отчёт, `Stop` — условия остановки.
Разделители и заголовки помогают читать инструкцию, но не меняют её приоритет.

Русские объяснения находятся в этом файле и руководстве разработчика. Загрузчик
`kit/run_opencode.py:prepare` читает только четыре перечисленных рабочих файла,
а этот README не добавляет к `system`. Пояснения здесь не скрыты от агента с
доступом к файлам, но не расходуют его контекст при автоматической загрузке роли.

HTML-комментарий внутри рабочего промпта (`<!-- пояснение -->`) модель тоже может
прочитать. Гарантированно игнорируемых моделью комментариев нет. Комментарий `//`
в JSONC вне строки исключается синтаксическим разбором и не входит в `system`.
Секреты нельзя помещать ни в промпты, ни в пояснения.

В `opencode.jsonc` остаётся короткая инструкция первоначального чтения файла.
Подготовка подставляет полный канонический текст в локальную надстройку;
самостоятельно редактировать сгенерированную копию не нужно.
