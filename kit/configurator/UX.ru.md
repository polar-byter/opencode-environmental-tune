# Настройка моделей проекта

Окно открывается кнопкой Settings в дашборде проекта. Для первичной настройки
можно попросить агента в OpenCode Desktop открыть конфигуратор этого проекта.
Агент запускает `py -m kit.configurator.app` из корня нужного проекта.

Выбор ролей, адреса API и имена переменных ключей сохраняются **для этой папки**
в `.opencode/kit-models.json`. Изменения не переключают модели других проектов.
Сам ключ хранится на уровне пользователя Windows. Папки с одинаковым именем
переменной используют один ключ; для разных ключей выберите разные имена.

## Разделы и язык

Вверху три крупные кнопки с иконками и пояснениями:

- **Master Chief — Planning & review**: модель для архитектуры, каркасов и проверки.
- **Executors — Code implementation**: модель для реализации; выбор используется
  обоими агентами `executor` и `executor-fast`.
- **OpenRouter — Model catalog & prices**: каталог для выбора модели любой роли.

По умолчанию подписи английские. **Language → Russian** включает русский явно.
Выбор сохраняется в `.metrics/.configurator-ui.json`; язык Windows его не меняет.
Переключение языка и раздела сохраняет поля, фильтры и незавершённые запросы.
Работают Tab/Space, стрелки на кнопках, Ctrl+Tab и Ctrl+Shift+Tab.

## Свой API

В разделе роли выбери **Own API** и заполни:

1. **API address**: базовый адрес, например `https://api.example.com/v1`,
   без `/chat/completions`, `/models`, параметров запроса и встроенного пароля.
2. **API key**: ключ скрыт маской; пустое поле сохраняет уже записанный ключ.
   Имя переменной выбирается автоматически и доступно в Advanced.
3. **Model**: точный идентификатор. **Get models** получает список с сервера;
   если сервис не поддерживает `/models`, имя можно ввести вручную.

Получение списка проверяет только `/models`, а не генерацию и работу инструментов.
Сетевые операции выполняются в фоне. Ошибки не раскрывают ключи или содержимое
ответов провайдера; ответ на устаревший запрос не перезаписывает изменённую форму.
Также доступны модели OpenCode и загруженные модели LM Studio.
Утилита не загружает и не выгружает модели LM Studio.

## Витрина OpenRouter

Каталог загружается при открытии раздела из публичного API без ключа.
Таблица показывает модель, контекст, поддержку инструментов и цены в USD
за миллион входных/выходных токенов. Доступны поиск, сортировка, фильтры цены,
инструментов и переключатель всех текстовых моделей.

Подборка для кода объединяет категорию programming с явными упоминаниями
программирования в названии/описании. Это способ отбора, а не рейтинг качества
или гарантия полного перечня пригодных для кода моделей. Неизвестные цены
обозначены прочерком; условные тарифы отмечены отдельно. Бесплатность определяется
из опубликованных ставок. Цены и наличие могут измениться.

Перед кликом выбери целевую роль над таблицей. Клик или Enter заполняет её черновик:
**Own API**, адрес `https://openrouter.ai/api/v1` и точный ID модели, включая `:free`.
**Role settings** открывает эту форму. Проверь ключ и сохрани настройки.
При переходе от другого провайдера его ключ не переносится в OpenRouter;
общий ключ OpenRouter можно ввести один раз для обеих ролей.

Клик по модели не сохраняет файл и не вызывает генерацию. Кеш каталога лежит в
`.metrics/.openrouter-catalog.json`; при ошибке загрузки видны источник и давность.

## Сохранение и применение

**Save settings** проверяет обе роли и сохраняет `.opencode/kit-models.json`.
В файле адрес, модель и имя переменной ключа; сам ключ сохраняется в пользовательской
переменной Windows. Это существующий способ хранения, а не шифрованное хранилище.
Невалидные поля и конфликт ключей одной переменной отклоняются до записи.

**Prepare OpenCode** сохраняет выбор и вызывает `run_opencode.py --prepare-only`:
собирает локальный `.opencode/opencode.jsonc`. Эта кнопка не перезагружает текущую
сессию. В Desktop агент выполняет подготовку общего сервиса по AGENTS.md;
для применения выбранного Мастер Чифа открой проект заново и начни новый чат.
Если только что добавлен API-ключ, полностью перезапусти Desktop из меню Windows,
чтобы приложение получило новое окружение. При необходимости перезапускается и
его фоновый сервис. Не передавай ключ сообщением в чат.

Сброс удаляет выбор моделей, но сохраняет ключи Windows.
Подробности: [LOCAL_MODELS.ru.md](../../LOCAL_MODELS.ru.md).
Повтор опыта: [DESKTOP_EXPERIMENT.ru.md](../../DESKTOP_EXPERIMENT.ru.md).

## Реализация, очистка и проверка

`desktop.py` содержит окно, `workflow.py` — проверку и сохранение,
`catalog.py` — таблицу, `openrouter.py` — получение и кеш каталога,
`i18n.py` — переводы, `icons.py` и `assets/` — иконки.
Для запуска нужны Python и Tk; Pillow нужен только для пересборки ресурсов.

После проверки ссылок удалён старый, больше не вызываемый класс `ConfiguratorApp`
из `app.py` и его неиспользуемый импорт `os`. В `app.py` оставлены учебные функции
преобразования формы, их комментарии, подготовка и совместимая точка входа.
Из `check_env.py` удалён неиспользуемый `http_get_json`: получение моделей
выполняется через `lmstudio_models.loaded_models`. Используемый POST сохранён.
Будущие учебные модули дашборда и тесты сохранены по его AGENTS.md.
SVG и генератор ресурсов нужны для редактирования иконок, PNG — для запуска,
ICO — для использования значка в Windows; они не являются случайными копиями.

Проверены 130 тестов конфигуратора, оба языка и окна 940×820 / 760×720.
Объединённый набор завершённого кода кита содержит 486 тестов;
будущие учебные заглушки дашборда в него не входят.
Результаты и визуальные снимки предыдущих проверок сохранены в `.metrics/configurator-*/`.
Учёт выпуска и очистки: `configurator-merge-20261015`.
Для доработки интерфейса пользователь явно разрешил реализацию основным помощником
после HTTP 429 выбранного Poolside. Успешное делегирование ему не заявляется.
